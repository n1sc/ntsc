# Rust adaptors

This final advanced chapter builds on
[Modules and imports](modules.md), [Error handling](error-handling.md), and
[Unsafe and raw pointers](unsafe-and-pointers.md). Start with the small local
crate example. The later generator-extension sections are for compiler
contributors, and can be revisited when you need an unsupported API.

Neutron generates Rust interop from dependencies declared in `[rust-deps]`.
Rust crate imports are **experimental** and disabled by default: a project
must opt in by adding this section to `neutron.toml`, or `ntsc build` fails
with a "disabled by default" error before any compilation happens. See the
[experimental features page](../reference/experimental.md) for the full list.

```toml
[experimental]
rust_modules = true
```

`ntsc cargo install` / `ntsc build` generate thin *adaptors* that the compiler
links into your binary, and each supported bridge becomes an ordinary call
in Neutron source. The goal is to use Rust crates directly, without writing
binders or changing upstream APIs. Coverage is not yet universal; this guide
explains what crosses the boundary and how to extend the shared generator.

The normative contract is [the autogen standard](../reference/rust-autogen.md);
this guide is the practical companion to it.

Autogen is crate-wide, not a hand-written binder per module. The generator
walks the dependency's reachable public `pub mod` graph and re-exports, then
finds public functions, impl methods, public fields, callback traits, and
supported type shapes. `ntsc build` emits one adaptor and one
manifest for the crate, so adding another public Rust module does not require
another Neutron-side binding file.

The long-term rule is **extend autogen once, never write per-crate binders**.
An API whose signature is already in the bridge vocabulary is generated
automatically. An unsupported signature is reported in the manifest with a
reason; support should be added to the shared classifier and emitter so every
crate benefits. “All Rust modules” means all reachable public modules, not that
arbitrary Rust types, lifetimes, generics, or unsafe semantics can be guessed
safely at an FFI boundary.

## Your first adaptor

A crate with one exported function is enough. This example uses a local
crate to keep it small; the same generator handles registry dependencies.
The Rust file contains application functionality, not hand-written binding
code. You do not need to create a wrapper crate for a supported upstream API.

```
myproject/
├── neutron.toml
├── rust/
│   └── mathish/
│       ├── Cargo.toml
│       └── src/lib.rs
└── src/
    └── main.nt
```

```toml
# rust/mathish/Cargo.toml
[package]
name = "mathish"
version = "0.1.0"
edition = "2021"
```

```rust
// rust/mathish/src/lib.rs
pub fn double(n: i64) -> i64 {
    n * 2
}
```

```toml
# Add this section to the neutron.toml generated by ntsc init.
# Keep the existing [package] section.
[rust-deps.mathish]
path = "rust/mathish"
```

```neutron
use @mathish

fun main() {
    say("" + @mathish.double(21))   // 42
}
```

`ntsc build` generates `.ntsc/mathish/` (a `Cargo.toml`, the generated
`src/lib.rs`, and `mathish.export.json`), compiles the archive, and links it.
`use @mathish` imports the module; calls are `@crate.function` or, for a
method on a returned object, `handle.method(...)`.

For a crate from crates.io, give a version instead of a path and let the
resolver do the work:

```toml
[rust-deps.serde_json]
version = "1"
```

The `[rust-deps]` key must match the crate's `package.name` exactly — a
mismatch is an error, not a lookup miss.

## What crosses the boundary

The bridge marshals a fixed vocabulary. Anything outside it is skipped with a
reason rather than miscompiled, which is why `ntsc cargo coverage` is worth
running on a new dependency. The exact ABI label is recorded in the generated
export manifest; parameter and return directions can use different handle
representations for option types.

| Rust | Neutron | Notes |
| --- | --- | --- |
| `i64`, `isize`, `u32`, … | `int` | |
| `f64`, `f32` | `float` | A `float` reaching an `int` slot is converted (saturating, NaN → 0). |
| `bool` | `bool` | |
| `String`, `&str` | `string` | |
| `Cow<str>` | `string` | The generated bridge reconstructs owned `Cow` storage. |
| `Vec<u8>`, `&[u8]` | `string` (bytes) | |
| `Cow<[u8]>` | `string` (bytes) | The generated bridge reconstructs owned `Cow` storage. |
| `Vec<T>`, `&[T]` for scalar `T` | `array[T]` | |
| `Option<T>` for scalar `T` | `option[T]` | A cell handle, not the scalar itself. |
| Supported `Option<String>` / `Option<Struct>` | nullable string / object handle | `None` is `0`; see the traps. |
| `Result<T, E>` | the success value | `Err` raises a catchable exception. |
| `Option<Vec<T>>` | `array[T]` | `None` is the null handle. |
| A supported owned struct | `object[T]` | Moves into the object registry; borrowed returns and field getters may require `Clone`. |
| `&T` / `&mut T` | borrowed | A `&mut` parameter is a mutable borrow for the call. |
| `self`, `&self`, `&mut self` | receiver | `Type_method(handle, …)`, also callable as `handle.method(…)`. |
| A unit enum variant | a value | `Enum::Variant` is a value, not a call. |

Public struct fields get accessors for free — `Dashboard_new(…)` plus
`Dashboard_set_latency(…)` and `Dashboard_latency(…)` appear with no code on
your side. Hand-written `impl` methods appear as `Type_method`.

## Traps

These are the ones that actually cost time. All of them are checked or
documented; the list is here so you meet them once.

**A hyphenated crate is spelled with an underscore in Neutron.** The package
`mewsic-tui` is imported as `use @mewsic_tui`. Both spellings resolve to the
same manifest entry, so this is safe — but writing the hyphen will not parse.

**Option representations depend on the payload.** Scalar options use option
cells. Supported `Option<Struct>` returns instead produce an object handle
for `Some` and `0` for `None`; check for `0` before calling an object accessor
or method. String and collection options likewise use nullable handles.
Consult the generated manifest instead of treating every option as a cell.
An unsupported option shape is a generator coverage gap, not a reason to
require a hand-written out-parameter wrapper.

**`Clone` is not required for every struct return.** Supported owned structs
move into the object registry. Borrowed object returns and generated getters
that preserve the source may need to clone; the current object-option return
bridge also clones its payload. Check the reported signature support rather
than adding `Clone` to every upstream type.

**Panic conversion depends on unwinding.** Generated calls use a
`catch_unwind` barrier to turn unwinding panics into Neutron exceptions.
An aborting panic cannot be caught; generation does not make an API's unsafe
preconditions or other runtime requirements disappear.

**Values move, including into a bridge.** A call consumes its arguments:

```neutron
@mathish.log(rows)      // `rows` is gone afterwards
@mathish.log(copy(rows))  // pass a copy to keep it
```

The same applies to reading a field you intend to reuse. Bind it to a local
first if the expression is not already a fresh value.

**Class instances cross as `view`.** `fun render(view Panel p)` — passing by
value is rejected for a class.

**String literals do not process escapes.** Building JSON in a literal with
`\"` sends a literal backslash to the other side. Use
`json.escape_string(s)` (which adds the quotes) or
`strings.from_char_code(34)`.

**Declare classes before the functions that read their fields.** A class's
LLVM struct type is created at its first use, so a function emitted earlier
that reads a later-declared class's field fails with `struct type … not
found`.

**A `float` cannot be cast with a type name.** There is no `float(x)`
expression: assign to a `float`-typed local and let the documented widening
apply, then do float arithmetic on locals.

## Inspecting what you got

```bash
ntsc cargo doc mathish              # summary + searchable HTML page
ntsc cargo doc mathish --no-open    # write the page without launching a browser
ntsc cargo coverage mathish         # manifest coverage counts
```

`ntsc cargo doc` prints a terminal summary, writes a searchable HTML page, and
opens it in the system browser. Use `--no-open` in SSH/CI environments. The
page shows exact Neutron calls, return types, Rust doc comments, callbacks, and
unsupported public signatures. It reads the generated export manifest as the
source of truth; run `ntsc build` to refresh it after changing the dependency
or generator.

## When autogen does not cover what you need

Do not create a one-off binder for a single crate. There are two different
problems, and both should be solved in the shared toolchain.

### The function is missing

First check the enabled Cargo features, public visibility, and re-exports.
A public re-export can expose an item from a private module. An item absent
from the manifest may indicate a discovery limitation, including a macro
shape the scanner does not understand. A discovered but unsupported signature
should have a reason in `ntsc cargo doc` / the export manifest.

For a reachable API that discovery misses, add a minimal Rust fixture and fix
the module, re-export, or macro discovery logic in
`crates/ntsc-cargo/src/adaptor.rs`. For a rejected signature, extend the type
support below. Do not add a crate-specific allowlist, hand-written binder, or
stdlib entry merely to bypass an autogen limitation. Stdlib additions need
their own language-level justification.

### The shape is missing

Add the shape to the shared autogen pipeline once; every dependency can then
use it without a binder. Adding a new marshalable shape touches five places,
in this order:

1. **`crates/ntsc-cargo/src/adaptor.rs`** — classify the Rust type into a
   `ParamKind` / `RetKind` variant, teach `param_type_name` /
   `ret_type_name` its label, and emit the marshaling in the bridge. Skip a
   shape rather than guessing: an entry marked unsupported with a reason is
   correct behaviour, a mis-marshaled one is a memory bug.
2. **The manifest** — the label goes into `mathish.export.json` through
   `ExportManifest` (`crates/ntsc-cargo/src/metadata.rs`). Bump
   `schema_version` for a breaking shape change; readers must ignore unknown
   fields, so additive labels do not need it.
3. **`crates/ntsc-codegen/src/emit/call.rs`** — `lower_rust_call_result`
   maps the label to a `Ty`, and the `Ty` decides the LLVM lowering.
4. **Tests** — classification tests in `adaptor.rs`, plus an end-to-end
   fixture in `crates/ntsc-cli/tests/rust_adaptor_e2e.rs` that generates and
   compiles the actual bridge. Codegen tests with a synthetic export manifest
   can isolate lowering, but do not replace a real generated-adaptor test.
   Cover ownership, errors, and cache invalidation as well as the happy path.
5. **Docs** — this guide, the [autogen standard](../reference/rust-autogen.md)
   label list, and the LSP completion list in
   `crates/ntsc-lsp/src/stdlib.rs` if the shape is callable by name.

Keep the generated manifest a pure function of the discovered API: entries
sorted, no timestamps, no absolute paths. `ntsc build` keys its adaptor cache
on the crate, version, target, profile, and features, and rebuilds when
`schema_version` or any generated file changes — so a non-deterministic
manifest defeats the cache.

## Keeping autogen fast

Broad coverage must not make every edit rescan and rebuild every dependency.
The current generator skips API discovery when its input fingerprint matches,
rewrites outputs only when their bytes change, and bundles multiple adaptors
into one Cargo build graph. These are a starting point, not a claim that
cold generation or unchanged builds are already fast enough.

Further work should measure cold generation, unchanged warm builds, and
single-dependency edits separately. Improve shared discovery, incremental
invalidation, and artifact reuse rather than replacing slow generation with
manual binders. See the [performance goals](../reference/rust-autogen.md#performance-goals)
for the development direction and validation criteria.

## Testing an adaptor

Application authors test their Rust functionality. Generator changes must
also test the generated bridges themselves:

```bash
cargo test -p <your-crate>          # the Rust side
cargo test -p ntsc-cargo            # discovery, emission, metadata, cache tests
cargo test -p ntsc-cli --test rust_adaptor_e2e <filter>
FILTER=<prefix> arq e2e   # targeted codegen coverage
```

Then build the real project and run it — a bridge that marshals wrong usually
fails at link time or on the first call, not at compile time.

## Checklist

- [ ] The crate compiles with no warnings; `#![deny(unsafe_code)]` if it can.
- [ ] `ntsc cargo doc <crate>` shows the entries you expect, with the return
      types you expect.
- [ ] No per-crate binder or workaround wrapper is required for supported APIs.
- [ ] New unsupported shapes have a generic implementation or an explicit diagnostic.
- [ ] Object ownership and nullable returns match the generated manifest.
- [ ] Real generated bridges are tested, including failure paths.
- [ ] Neutron-side call sites respect move semantics (`copy` where reuse is
      needed).
- [ ] Cold/warm generation and cache invalidation are checked for performance changes.
- [ ] Docs updated: this guide and the autogen standard.
