# Packages

You can now split a program into files and import the standard library. This
chapter shows how to depend on code that lives in someone else's repository,
and how to publish your own module so others can do the same.

`ntsc pkg` is the package manager. It reads dependencies from
`neutron.toml`, resolves them against the [NTSC registry][registry], copies
the matching releases into `.ntsc/`, and records the result in
`neutron.lock`.

## Adding a dependency

From the project directory:

```console
$ ntsc pkg install slug

  > neutron modules
  resolving 1 dependency
  ok slug v1.2.0
  ok installed 1 package
  linked into .ntsc/
```

This writes a line into `neutron.toml`, resolves the newest version that
satisfies the requirement, vendors it, and updates the lockfile. If you
already know the requirement you want, pass it after `@`:

```console
$ ntsc pkg install slug@~1.2
```

Or edit the manifest yourself and run `ntsc pkg install` with no arguments:

```toml
[package]
entry = "src/main.nt"
output = "hello"

[dependencies]
slug = "^1.2.0"
```

The dependency table sits beside `[package]`; comments and unrelated tables
are preserved when `ntsc pkg` edits the file.

## Importing a package

A package is imported by its name, exactly like a standard-library module:

```ntsc
use slug

fun main() {
    say(slugify("Hello, World!"))
}
```

The compiler looks for `.ntsc/<name>/lib.nt`, or `.ntsc/<name>/src/lib.nt`
for a package that keeps its sources under `src/`. The search happens at the
project root, so a project whose entry is `src/main.nt` still finds its
packages in the top-level `.ntsc/` directory.

Package imports behave like any other file import: only the entry file needs
`main`, and names from the package are merged into the same namespace.

## What installation produces

```
hello/
├── neutron.toml
├── neutron.lock        resolved versions and checksums
├── .ntsc/
│   ├── .gitignore      contains "*"
│   └── slug/
│       ├── lib.nt
│       └── neutron.toml
└── src/main.nt
```

`.ntsc/` is a build artifact — it is reproducible from `neutron.lock`, so the
generated `.gitignore` keeps it out of version control. Commit
`neutron.lock`; it pins the exact versions and the SHA-256 of each vendored
tree so every machine builds the same code.

One project is an exception: the package manager itself commits its
`.ntsc/toml/` tree, because `ntsc-pkg` cannot fetch its own dependency before
it exists.

The lockfile is plain TOML:

```toml
# Generated by `ntsc pkg`; run `ntsc pkg install` to refresh it.
version = 1

[packages]
slug = "1.2.0"

[sources]
slug = "https://github.com/you/ntsc-slug"

[integrity]
slug = "sha256:9f2c…"
```

`ntsc pkg install` reuses a locked version while it still satisfies the
manifest; `ntsc pkg update` ignores the lockfile and re-resolves everything.

## Requirements

A requirement is a version, a range, or a comma-separated list of ranges. All
of these are valid in `[dependencies]`:

| Requirement | Accepts |
| --- | --- |
| `"1.2.0"` | Exactly `1.2.0`. |
| `"1.2"` | Any `1.2.x`. |
| `"1"` | Any `1.x.y`. |
| `"^1.2.0"` | `>=1.2.0, <2.0.0` — the default when you `install`. |
| `"~1.2.0"` | `>=1.2.0, <1.3.0`. |
| `">=1.2.0"`, `"<2.0.0"` | An open bound. |
| `">=1.2.0, <1.5.0"` | Both clauses must hold. |
| `"*"` | Any release version. |

Prereleases (`2.0.0-beta.1`) are only selected when the requirement names a
prerelease, so a range such as `>=1.0.0` never quietly picks up a beta.

If no published version satisfies the requirement, installation fails with
`no version satisfies '<requirement>'`.

## Managing dependencies

| Command | Effect |
| --- | --- |
| `ntsc pkg install` | Install everything in `neutron.toml`, reusing `neutron.lock`. |
| `ntsc pkg install <name>` | Add `<name>` at `^<latest>` and install. |
| `ntsc pkg install <name>@<req>` | Add `<name>` with an explicit requirement. |
| `ntsc pkg update` | Re-resolve to the newest allowed versions. |
| `ntsc pkg remove <name>` | Drop the dependency and unvendor it. |
| `ntsc pkg list` | Print the packages recorded in `neutron.lock`. |
| `ntsc pkg search <query>` | Search the registry by name, description, and keywords. |

`search` is case-insensitive and prints the latest version next to each
match:

```console
$ ntsc pkg search slug
  slug 1.2.0
    URL-friendly slugs from arbitrary text
```

Transitive dependencies are resolved too: if `slug` depends on `text`, both
are vendored, and `ntsc pkg list` shows both. Removing a package also removes
anything that only it required.

## Publishing a package

The registry lives in [n1sc/registry][registry]. Adding a package is a pull
request that adds one file, `packages/<name>.toml`:

```toml
[package]
name = "slug"
description = "URL-friendly slugs from arbitrary text"
repo = "https://github.com/you/ntsc-slug"
license = "MIT"
keywords = ["slug", "text"]
```

Versions are discovered from your repository's git tags, so a release is just
a tag — there is no second list to keep in sync. Tag with semantic versions
(`v1.0.0`, `v1.1.0`, …) and make sure the repository:

- is publicly reachable over `https://`, `http://`, `ssh://` or `git@`,
- has `neutron.toml` at the root with a `[package]` table,
- exports its API from `lib.nt` or `src/lib.nt` at that root.

Once the pull request merges, CI rebuilds the index and
`https://ntsc.yasakei.dev/v1/registry` serves it within a few minutes. See the
repository's [CONTRIBUTING][contributing] for the field table and review
criteria.

## Mirrors and self-hosting

`ntsc pkg` reads the index from `https://ntsc.yasakei.dev/v1/registry`. Point
`NTSC_REGISTRY` at another URL to use a mirror or a private index:

```console
$ NTSC_REGISTRY=http://localhost:8000/index.json ntsc pkg install
```

The index is a single JSON document; any HTTP server that returns
`{"version": 1, "packages": [...]}` works.

Package sources are cloned with `git` into a per-user cache under
`~/.ntsc/packages/`, so switching projects or reinstalling does not download
the same tag twice. Delete that directory to force a fresh clone.

## Try it

Publish the `slug` module: create a repository with `lib.nt` and a
`neutron.toml`, tag `v1.0.0`, then add `packages/slug.toml` to the registry
with a pull request. Once CI rebuilds the index, install it into a second
project with `ntsc pkg install slug`, import it with `use slug`, and
call a function.

Then run `ntsc pkg list` and open `neutron.lock` to see the version and
checksum that were recorded. Delete `.ntsc/` and run `ntsc pkg install` again;
the lockfile should restore the same tree.
